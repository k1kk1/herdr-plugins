# Pane Manager の内部実装

Herdr の API には「できないこと」がいくつかあり、その上で仕様どおりの操作を
成立させるために内部で組み替えています。ユーザーには見せない部分の記録です。

API 側の制約そのものは [../docs/herdr-api.md](../docs/herdr-api.md) にまとめてあります。

---

## Cross-tab Swap の内部処理

Herdr の `pane.swap` は同一 Tab 内でしか動かず、Tab をまたぐと `reason: "cross_tab"` を返します。
そこで2回の `pane.move` でエミュレートしますが、**空になった Tab は Herdr が自動的に閉じる**ため、順序を選ぶ必要があります (spec §6.2)。

| 状況 | 手順 |
|---|---|
| 両 Tab に他の Pane がある | A を B の隣へ → B を A の元位置へ |
| A が単独 | 先に B を A の Tab へ → その後 A を移動 |
| B が単独 | 先に A を B の Tab へ → その後 B を移動 |
| 両方とも単独 | A を B の隣へ (A の Tab は閉じる) → B を新 Tab へ切り出し、元の Tab 名を引き継ぐ |

最後のケースでは Tab を作り直しますが、元の Tab 名と Tab バー上の位置を引き継ぐため、
ユーザーから見ると単に2つの Pane が入れ替わったように見えます。操作後の通知でその旨を伝えます。

## Left / Up の内部変換 (追加仕様 §9)

Herdr の split は Right / Down しかありません。Left と Up は

```
Split Right / Down
↓
Swap（同一 Tab 内）
```

に内部変換しています。比率指定は「元からあった Pane の取り分」で一貫させているため、
`60:40` は Left でも Right でも「元の Pane が 60%」になります。

## Merge のレイアウト保持 (追加仕様 §11)

移動元 Tab の split 構造を、そのまま1グループとして統合先へ持ち込みます。

```
Before                          After

Tab 1     Tab 2                 Tab 1
A         ┌──────┬──────┐       ┌───┬─────────────┐
          │ B    │ C    │       │ A │ ┌────┬────┐ │
          ├──────┴──────┤       │   │ │ B  │ C  │ │
          │ D           │       │   │ ├────┴────┤ │
          └─────────────┘       │   │ │ D       │ │
                                └───┴─────────────┘
```

`preserve_merge_layout = false`、または `--flatten` で単純な直列 Split になります。

## 実行後の検証 (追加仕様 §8)

API が成功を返しただけでは完了扱いにしません。操作後に pane を読み直し、
期待する Tab に居ること・元の Tab から消えていること・Swap 対象が入れ替わっていることを確認します。
確認できない場合は `Move could not be verified.` のようなエラーを出します。

エラー画面では `r` で最新状態を取り直してピッカーをやり直せます (追加仕様 §7)。
