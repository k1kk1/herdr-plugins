# 共有 UI の規約

4つのプラグインは `herdr-plugin-kit` の同じピッカーを使っています。
画面ごとに操作方法が変わらないようにするための取り決めです。

---

## キー

### 常に同じ意味を持つキー

| キー | 意味 |
|---|---|
| `↑` `↓` / `j` `k` / ホイール | カーソル移動 |
| `Enter` / クリック | 決定（クリックは1回目で選択、2回目で決定） |
| `Esc` / `Ctrl+C` / `Ctrl+D` | 何もせず閉じる |
| `q` | 閉じる（絞り込み画面を除く） |
| `1`–`9` | その番号の項目を即選択 |

### `j` `k` は対称でなければならない

メニューは `j` と `k` を **両方束縛するか、どちらも束縛しないか**のどちらかです。
**片方だけは禁止**です。

これは実際に踏んだ不具合です。Pane Manager が `j` を Merge に、Layout Tools が `k` を
Main Top に割り当てていたため、

- Pane Manager では `j` が Merge を実行し、`k` はカーソルが動く
- Layout Tools では `k` が Main Top を実行し、`j` はカーソルが動く

と、**同じ列の中で `j` と `k` の意味が食い違い、しかもプラグイン間で逆**になっていました。
Merge は `c`（Combine）へ、Main Top は `t` へ移しています。

例外は**方向ピッカー**です。`h` `j` `k` `l` を左下上右として4つとも束縛するので、
半端に残る側がありません。

実装は `Menu::claims_both_vim_keys()` で、片方だけ束縛したメニューを描画しようとすると
デバッグビルドで `debug_assert` が落ちます。

### 絞り込み画面では `q` を案内しない

文字入力を受け付ける画面では `q` は検索文字になります。
フッターの文言もそれに合わせて出し分けます。

```
絞り込みあり:  type to filter · ↑↓ move · 1-9 pick · Enter select · Esc cancel
絞り込みなし:  ↑↓ move · Enter select · q / Esc cancel
```

数字だけは絞り込み中でも項目選択に使います。番号を検索したい場面はほぼ無く、
Quick Move の `1`–`9` を失うほうが困るためです。

### 番号は画面に見えているものに振る

`Menu::numbered()` を付けた一覧は、**絞り込み後の並び**に `1`–`9` を振り直します。
メニュー構築時に固定番号を振ると、行 3・7・20 が絞り込みを生き延びたときに
`3` `7` と歯抜けで表示され、見えている順番と食い違います。

Navigator と Command Palette はこれを使っています。長い一覧ほど番号が要るのに、
以前はこの2つにだけ番号がありませんでした。

## 一覧の表示

### 画面に収まらないときはスクロールする

行数ではなく **行の高さ**で計算します（`detail` 付きの行は2行を占めるため）。

- カーソルが画面内にいる限りリストは**動かない**。端を越えたときだけ送る
- 右下に残件数を出す（`↑ 3   ↓ 12`）
- クリック位置は画面上の位置ではなく**全体での行番号**に対応させる

以前はビューポートが無く、`height-2` で描画を打ち切って `…` を出すだけでした。
カーソルは全項目を巡回するので、**`…` の先へ降りるとハイライトが画面外に消え、
何を選んでいるか見えないまま Enter を押せる**状態でした。

計算は `scroll_for()` に切り出してテストしてあります。
実際の Command Palette の形（33 actions + 見出し3 + 区切り2 = 38行、popup 37行）で、
先頭から末尾まで矢印で到達できることを確認しています。

### 1項目 = 1行を基本にする

`secondary`（薄い補足）は同じ行の末尾に連結します。
`detail`（ターミナルタイトルなど）だけが2行目を使います。

## ポップアップの寸法

| プラグイン | 幅 × 高さ | 理由 |
|---|---|---|
| Pane Manager | 60% × 70% | Tab 一覧 + 操作。最大 21 行 |
| Layout Tools | 50% × 60% | 項目が10行未満で固定 |
| Navigator | 70% × 70% | Pane 数に比例して伸びる |
| Command Palette | 70% × 70% | 全プラグインの Action が並ぶ |

伸びうる2つを広くしています。それでも溢れるのでスクロールが要ります。

## 表示名

内部 ID (`w1:p3`) は原則として出しません（spec §3.2）。

```
1. Pane label
2. Agent 名
3. cwd basename / Project 名
4. terminal title
```

```
● Claude · mushi-battle
    Stackchan⇔CoreS3 ESP-NOW無線通信対応
```

Agent の状態は記号で添えます。

| 記号 | 状態 |
|---|---|
| `●` | working |
| `!` | blocked |
| `✓` | done |
| `○` | idle |
| `?` | unknown |

`show_ids = true` と `doctor` サブコマンドのときだけ生 ID を出します。

### 幅の計算は CJK を2桁で数える

`truncate()` は日本語を2カラムとして数えます。
末尾に `…` を足す前に、はみ出さないところまで文字を落とします。

## 操作の一貫性

### 状態をキャッシュしない

ピッカーを開く直前と、操作を実行する直前の2回、Herdr から読み直します（追加仕様 §7）。
ピッカーを開いたまま放置しても、その間に Agent が Pane を動かしていても破綻しません。

### 実行後に確認する

API が成功を返しただけでは完了扱いにしません。Pane を読み直して、
期待する Tab にいること・元の Tab から消えていることを確認します（追加仕様 §8）。
確認できなければ `... could not be verified.` を出します。

失敗画面では `r` で最新状態を取り直してやり直せます。

### 勝手に動かさない

どのプラグインも、ユーザーが操作しない限り Pane を動かしません。
Gather も Agent の状態を監視して自動で組み替えたりはしません（追加仕様 §14）。
