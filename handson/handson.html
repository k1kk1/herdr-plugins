状況をつくって、7回だけ手を動かす

キーの一覧を眺めても手は覚えません。ここでは handson.sh で「困っている状況」を実際に組み立てて、 そこから抜け出す操作を1回ずつ試します。全部終えて15〜25分。壊れても clean で消えます。

  • prefix = Ctrl + B
  • 7 シナリオ
  • ~/src/herdr-plugins/handson
  • プロセスは止まらない

Drills

00準備 01Agentを集める 02迷子のPane 03切り出す 04畳み込む 05入れ替える 06形を整える 07探して飛ぶ 08設定一覧 09片付け

0 / 7 完了

準備

必要なのは、4つのプラグインが link されていることと、キーバインドが入っていることの2つだけです。

確認
# 4つとも enabled になっていること
herdr plugin list

出ていなければ herdr plugin link ~/src/herdr-plugins/herdr-pane-manager を 4つのディレクトリぶん実行します。link 時に cargo build --release も走ります。

キー
キー開くもの担当
prefix + mPane ManagerPaneがどのTabに属するか
prefix + alt + lLayout ToolsTabの中のどこに置くか
prefix + fNavigator探して飛ぶ。何も動かさない
prefix + alt + pCommand Palette全Actionの横断検索

これは ~/.config/herdr/config.toml に設定済みです。変えたら herdr server reload-config、または prefix shift R。

練習環境
cd ~/src/herdr-plugins/handson

./handson.sh list          # シナリオ一覧
./handson.sh setup all     # 7つ全部を用意する
./handson.sh status        # 今なにがあるか
./handson.sh arm gather    # Agentの状態だけ入れ直す
./handson.sh order         # ドリル順に並べ直す
./handson.sh reset gather  # 1つ作り直す
./handson.sh clean         # 片付ける

Workspaceは ハンズオン 1: gather … ハンズオン 7: navigator という名前で作られ、 実作業のWorkspaceの後ろにドリル順で並びます。 順番が崩れたら order を打てば並べ直せます。

clean は3つの条件を満たすWorkspaceしか閉じません。 ラベルが ハンズオン で始まること、中のPaneが全部このスクリプトの作ったものであること、 そしてスクリプト自身が動いているWorkspaceでないこと。 練習中に自分の作業Paneを持ち込んでしまったWorkspaceは、巻き添えを避けるためスキップして警告を出します。 中身ごと閉じてよいと分かっているときだけ clean --force を使ってください。

done は「終わったのに、まだ見ていない」という意味の状態です。 Herdr は working → idle の遷移を done として覚え、 そのPaneのあるTabを開いた瞬間に idle へ落とします。 つまりシナリオを見て回るだけで done は溶けます。仕様どおりの動きです。

そのためドリル01は、溶けないAgentを4体（blocked 2 + working 2）置いてあります。 Tabを全部開いたあとでも 4 で 2×2 がきっちり埋まります。 done はその上に乗る5体目で、./handson.sh arm gather を打つと復活します。 arm はレイアウトを一切触らず、記録しておいた状態を報告し直すだけです。

返事待ちのAgentが、別のTabに埋もれている

Pane Manager · Gather

状況

5つのAgentが3つのTabに散らばっています。2つは入力待ちで止まっていますが、別Tabなので気づけません。 同じWorkspaceには dev server の Pane もありますが、これは Agent ではありません。

blocked · auth review blocked · api docs working · auth tests working · changelog done · db migration agent無し · dev server

./handson.sh setup gather
./handson.sh status   # 「Gatherが今すぐ拾う数」を確認

status の最後に Gatherが今すぐ拾う数 が出ます。 キーを押す前にここを見れば、何枚集まるはずかが分かります。

  • 5つ目は溢れて2枚目のTabへ。blocked → done → working の順に詰められます。
  • 最優先の blocked に自動でFocusが移るので、そのまま返事を打てます。
  • dev server は連れて行かれません。Agentとして検出されていないPaneは対象外です。
  • 押した 4 は1Tabの上限であって目標数ではありません。 対象が3体なら3枚しか入りません。集まった数が想定と違うときは、まず対象が何体あるかを ./handson.sh status で確かめてください。
  • done の1体は、migration Tabを開くと消えます。 Tabを見て回ってから Gather すると 4 + 0、 直前に ./handson.sh arm gather を打つと 4 + 1 になります。 どちらも正常です（理由は下）。
  • 2回目以降の Gather / Refresh は同じ Active Agents Tab を使い回します。 Tabが増え続けたり、並び順の末尾に飛んでいったりはしません。
続けて CtrlB→M→G→2 左右2分割で組み直す
戻す CtrlB→M→R Restore

Restore のあと review と migration のTabが戻っているか見てください。 最後のPaneが出ていった時点で Herdr がTabを閉じているので、Pane Manager が 同じ名前・同じ並び順で作り直しています。 「3 tabs rebuilt under their original names」と出れば成功です。

Gather は自分からは絶対に動きません。Agentの状態が変わってもPaneは勝手に移動しないので、 入力中に画面が動くことはありません。組み直したいときだけ G を押します。

なぜ作業中のTabに集めず、専用のTabを作るのか。 集めたPaneは元のTabから引き抜かれてくるので、Restore で戻せなければいけません。 作業中のTabに混ぜてしまうと、そのTabが Gather のたびに書き換わり、 戻したあとも元の形に復元できなくなります。2/3/4 の決まった配置も、 先客が居るTabには当てはめられません。 専用Tabなら中身が全部 Gather のものなので、そのまま畳んで捨てられます。

設定
max_panes_per_tab = 4
1Tabに詰めるPane数。2 / 3 / 4 のみ。画面が狭いなら 2 が読みやすい。
statuses = ["blocked", "done", "working"]
["blocked"] にすると本当に止まっているものだけ集まる。通知の代わりに使うならこれ。
focus_highest_priority = true
false にすると集めるだけでFocusは動かない。画面を見てから決めたいとき。
scope = "workspace"
"all" で全Workspace。メニューからは W / A で1回だけ切り替えられる。
agents = []
["codex"] のように種別で絞れる。空なら全種別。
tab_label = "Active Agents"
生成されるTabの名前。複数枚になると末尾に番号が付く。
# ~/.config/herdr/plugins/config/pane-manager/config.toml
[pane-manager.gather]
statuses = ["blocked"]
max_panes_per_tab = 2
02

Paneを置く場所を間違えた

Pane Manager · Quick Move / Move

状況

Tabが6つある Workspace です。editor Tab の下に deploy log が居ますが、 本当は deploy Tab に置くつもりでした。

準備
./handson.sh setup move
操作

deploy log のPaneにFocusを置いてから:

CtrlB →M →5 deployは5番目のTab

番号を覚える必要はありません。オーバーレイを開くと、いちばん上に Quick move current pane to としてTab一覧が番号付きで並びます。見えている番号を押すだけです。

結果

確認もアニメーションもなく、即座に移動します。ログを流しているプロセスは止まりません。

10個目以降のTabへ CtrlB→M→M →"dep" と入力→Enter

絞り込みは Workspace名 / Tab名 / Agent名 / cwd / ターミナルタイトルを横断します。 hp でも plug でも herdr-plugins に当たります。

やり直したくなったら CtrlB→M→U Undo

Move / Extract / Merge / Swap は1段階だけ戻せます。 戻せるものがあるときだけ U がメニューに出て、 「take back the Move deploy log」のように何を戻すかが副題に出ます。 元の Tab が空になって閉じられていた場合は、同じ名前・同じ位置で作り直されます。

設定
default_move_direction = "right"
"ask" にすると移動のたびに方向を聞かれます。 H 左 / J 下 / K 上 / L 右。 Herdr 自体は右と下にしか分割できませんが、左と上は内部で分割＋交換に変換されるので、4方向とも使えます。
default_split_ratio = "50:50"
"ask" で 50:50 / 60:40 / 40:60 を選べる。左の数字が元からあるPaneの取り分。
advanced_move = false
true にすると「移動先Tabのどの Pane を分割するか」を毎回選べる。既定では移動先Tabがフォーカスしている Pane が分割される。
# 方向とサイズを毎回選ぶようにする
[pane-manager]
default_move_direction = "ask"
default_split_ratio = "ask"

Quick Move（数字キー）は設計上なにも聞きません。"ask" にしても即実行のままです。

preserve_merge_layout = false
confirm_merge = true

CLI からは --flatten で1回だけ平らにできます。

準備
./handson.sh setup swap
操作

結果

2つのPaneが位置を入れ替えます。中で動いているプロセスはどちらも継続します。

ピッカーはTabごとにグループ化されているので、別Tab・別WorkspaceのPaneとも交換できます。 他のハンズオンWorkspaceのPaneを選んでみてください。Herdr の pane.swap は同一Tab内しか対応していないので、 別Tab同士のときは Pane Manager が内部で分解して実行しています。操作としては同じ1手です。

自分のClaude Codeやシェルが動いているPaneは選ばないでください。 交換するとその Pane がハンズオンWorkspaceの中に入り、あとで clean の対象範囲に紛れ込みます。 clean 側でも「よそのPaneが入っているWorkspaceは閉じない」ようにしてありますが、 練習はハンズオンWorkspace同士で完結させるのが安全です。 うっかり持ち込んでしまったら ./handson.sh status が名指しで教えてくれます。

設定
focus_after_operation = true
交換後、動かしたPaneにFocusが移ります。別Tabと交換した場合はそのTabへ飛ぶということです。false なら今の場所に留まります。
show_agent_state = true
ピッカーに ● ! ✓ ○ ? の状態記号が出ます。どのPaneでAgentが待っているかを見ながら選べます。
show_terminal_title = true
Paneの2行目に「今なにを実行しているか」が出ます。名前が似たPaneを見分けるのに効きます。

片付けと、つまずいたとき

片付け
./handson.sh clean

Gather したまま片付けても大丈夫です。閉じられたPaneは Restore のときに 「closed while gathered」として報告され、残りのPaneはちゃんと元の場所に戻ります。

閉じられなかったWorkspaceがあると、理由を名指しで出します。 よくあるのは2つ。よそのPaneが入っている場合は、そのPaneを別のWorkspaceへ移してからもう一度。 スクリプト自身が動いているWorkspaceだった場合は、別のWorkspaceのシェルから実行し直してください （自分の足元を閉じると、そこでシェルごと止まって残りが片付きません）。

困ったら
  • どの画面も Q / Esc で何もせず閉じます。
  • J K は常にカーソル移動です。方向を選ぶ画面だけは H J K L の4つとも方向になります。
  • 一覧が画面に収まらないときは自動でスクロールし、右下に ↑ 3 ↓ 12 のように残りの件数が出ます。
  • 操作が失敗したら R で最新状態を取り直してやり直せます。Herdr 側で状況が変わっていた場合です。
  • 集まる数が想定と違う → ./handson.sh status の「Gatherが今すぐ拾う数」を見る。
  • done が消えている → ./handson.sh arm <名前>（Tabを開くと消えます）。
  • 今どうなっているか分からない → ./handson.sh status。
  • プラグイン側から見えている状態を知りたい → ~/src/herdr-plugins/herdr-pane-manager/target/release/herdr-pane-manager doctor。 全 Workspace / Tab / Pane の構造と、集約セッションの中身が ID 付きで出ます。
覚え方

全部を一度に覚える必要はありません。CtrlB M と CtrlB F の2つだけ体に入れば、残りはオーバーレイに全部書いてあります。
